# wolysh v0.6.0: background runs, sessions and output questions

Wolysh 0.6.0 adds two features for agents and long-running work, and closes
most of the remaining gaps with Bash.

- **Background runs and sessions.** `run -d` keeps a command running after
  the call that started it ends, keeps every byte of its output, and answers
  `status` and `logs` in under a millisecond. `session` keeps a named
  shell whose directory, variables and functions persist between calls, with
  a tmux-like `attach`.
- **Questions about output.** `out` answers "which tests failed", "what went
  wrong" and "where is the line about X" within a byte budget, so a 10,000-line
  test log does not have to be read in full.
- **Bash compatibility.** Namerefs, call-stack variables, Bash's array rule for
  `$name`, every `set -o` and `shopt` name, `lastpipe`, `let`, `PS0` and the
  exported-variable rules now match Bash. nvm's `nvm.sh` and its 156 fast tests
  behave the same under wsh as under Bash.

## Highlights

```sh
wsh run -d --name test -- cargo test      # returns at once
wsh run wait test --match 'test result'   # block until a line appears
wsh run logs test --failures              # only the failed tests and counts
wsh run logs test --budget 4k             # a summary that fits in 4 KB
wsh run logs test --find 'connection refused'

wsh session new work
wsh session exec work -- 'cd src && export MODE=dev'
wsh session exec work -- 'pwd; echo $MODE'  # src, dev
wsh session attach work                      # Ctrl-\ then d detaches
```

- **Runs:** `run -d/status/wait/logs/kill/rm`. Each run's `meta.json` and
  append-only `output.log` live under `$XDG_RUNTIME_DIR/wsh` (or
  `/tmp/wsh-<uid>`), so a run records its exit status even if nothing is
  watching it. `wait --match`, `--timeout`, and `logs --since OFFSET` for
  polling.
- **Sessions:** `session new/ls/exec/attach/kill`, served by a per-user daemon
  on a 0600 socket that checks the caller's uid. Attaching gives a terminal
  that survives detaching: the foreground command keeps running, the newest
  64 KiB is replayed on the next attach, resizes reach the session, and a slow
  client slows the output down as under tmux.
- **`out`:** `budget`, `find` (fzf-style ranking), `grep`, `failures` (cargo,
  pytest, Go, Jest, Vitest, Zig, unittest, Maven/Gradle, Mocha, RSpec),
  `lines` and `stats`, over stdin, `--file` or `--run NAME`, with `--json`.
- **Bash:** `declare -n`, `FUNCNAME`/`BASH_SOURCE`/`BASH_LINENO` stacks,
  `BASH_VERSION` and friends, `shopt -s lastpipe` and `inherit_errexit`,
  `PS0`, `PROMPT_COMMAND` arrays, `HISTTIMEFORMAT`, `wait -p`, `printf -v`
  into array elements, and scripts without a `#!` line.

## Upgrading from 0.5

These changes can alter what existing scripts do:

- `$name` on a Bash array is element 0, as in Bash. Lists bound with `let`
  still expand to every element.
- Scripts expand aliases only after `shopt -s expand_aliases`, as in Bash;
  interactive shells are unchanged. In scripts `which` is the external
  program.
- A failed arithmetic expansion (`$((1/0))`) or an assignment to a readonly
  variable ends a non-interactive shell.
- Input that ends inside a quote is a syntax error.
- The not-found message reads `wsh: NAME: command not found`.
- `wsh run` and `wsh session` are the new commands; to run a script file with
  one of those names, write `wsh ./run`.

## Known differences from Bash

- `<` and `>` in `[[ ]]` compare bytes rather than the locale's collation
  order.
- `declare -f` prints a function as written, not reformatted.
- Aliases expand when a command runs, not when it is read.
- Interactive-only `shopt` names such as `cdspell` and the `compat*` levels are
  accepted but change nothing.

## Install or upgrade

Download `wolysh-v0.6.0-linux-x86_64.tar.gz` and its `.sha256` file:

```sh
sha256sum -c wolysh-v0.6.0-linux-x86_64.tar.gz.sha256
tar -xzf wolysh-v0.6.0-linux-x86_64.tar.gz
mkdir -p "$HOME/.local/bin"
install -m 0755 wolysh-v0.6.0-linux-x86_64/wsh "$HOME/.local/bin/wsh"
"$HOME/.local/bin/wsh" --version
```

## Verification

CI and the release workflow build for baseline x86_64, check that the tag
matches `wsh --version`, and run the unit, interactive and compatibility suites
before packaging. Most compatibility suites run each case in wsh and in Bash and
require the same output and exit status.

- 387 unit tests
- 37 interactive checks
- 414 compatibility tests, including 91 whole-script comparisons with Bash
- 50 tests for runs, sessions and `out`

The [recorded benchmark run](https://github.com/dev-dami/wolysh/blob/v0.6.0/benchmarks/README.md#recorded-agent-feature-run)
measures the new commands against their nearest Bash counterparts: `run status`
answers in 0.76 ms and `out failures` reads a 20 MB test log in 19 ms. The
shared workloads are within noise of the build just before these features
(commit `b5b8232`, which already includes changes made after the 0.5.0 tag).
