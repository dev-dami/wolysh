# Plan for wolysh 1.0

This page lists what 1.0 must contain, the features to announce, the state of
Bash compatibility, and how wolysh runs Bash scripts more safely than Bash.
Items marked **(proposed)** are not built yet.

## Release gates

Tag `v1.0.0` only when all of these are true:

- [ ] CI is green: format check, unit tests, release build, every
      `tests/*_test.py` file, and the Memory guard job.
- [ ] The job "Test suite under the memory guard" is green, and it blocks
      merges. Every test then also runs on a Debug build with the checking
      allocator, where overflow and bounds errors panic.
- [ ] `tests/guard_cases.sh` has a case for each memory, overflow or hang bug
      that was fixed.
- [ ] A corpus of real Bash scripts runs with the same output under `wsh` and
      `bash` **(proposed: see "Compatibility corpus")**.
- [ ] Each item in "Known differences from Bash" is fixed or written in the
      language guide.
- [ ] The release notes in `docs/releases/v1.0.0.md` contain the feature list
      below.
- [ ] The binary sizes in the CI log did not grow more than 2% from 0.6.0
      without a reason (see [memory.md](memory.md)).

## Features to announce

### Runs your Bash scripts

- Most Bash scripts run unchanged: `case`, `until`, `[[ ]]`, `(( ))`, C-style
  `for`, functions, namerefs, indexed and associative arrays, Bash parameter
  expansion, process substitution, extended globs, here-documents and here
  strings, coprocesses, traps and `set -euo pipefail`.
- The Bash builtins that scripts use are there, for example `declare`,
  `local`, `read`, `mapfile`, `printf` (with `%(...)T`), `getopts`, `trap`,
  `shopt`, `complete`, `fc`, `bind` and `enable`.
- nvm's `nvm.sh` and its fast tests behave as under Bash.

### A readable language next to Bash

- `let`, `env`, `if`, `for`, `while` and `fn` with real expressions:
  `let count = 4 * (10 + 2)`, `if count > 10 { ... }`.
- Expression functions: `exists`, `is_dir`, `split`, `join`, `trim`,
  `starts_with`, `env` and others.
- Commands stay commands. A line that does not start with a keyword runs as a
  command, so Bash habits keep working.

### Built for developers and agents

- `wsh --check` checks the syntax of a script or of standard input and runs
  nothing.
- `parallel -j N` runs tasks in child processes, with `--fail-fast` and JSONL
  reports.
- `wsh run -d` keeps a background command and all its output after the caller
  exits. `run wait`, `run logs --since` and `run status --json` follow it.
- `wsh session` keeps named shells with their directory, variables and
  functions between calls, and lets you attach to their terminal.
- `out` answers questions about long output within a byte budget: a summary,
  the failed tests, or the lines that match a fuzzy query.

### A good interactive shell

- Syntax highlighting, history suggestions, `Ctrl-R`, completion with Bash
  `complete` specs, vi and emacs modes, and job control.
- Typo suggestions with a prefilter, so normal command lookup stays fast.

### Fast and small

- One static binary with no runtime dependencies. In CI, the release build
  is 1,788,072 bytes and the size-optimized build is 1,010,816 bytes.
- Startup and loop speed are measured against Bash in
  [benchmarks/README.md](../benchmarks/README.md).

## Bash compatibility

### How it is checked

- 386 unit tests in `src/`.
- About 325 end-to-end tests in `tests/compat_*_test.py` and
  `tests/shell_compat_test.py`. Nine of these files run Bash next to wsh
  and compare the results.
- `tests/compat_scripts_test.py` runs nvm's own tests.

### Known differences from Bash

These come from the [language guide](language.md#known-limitations):

- A list bound with `let` expands to all its elements as `$name`. A Bash
  array gives element 0, as in Bash.
- Regular expressions with back-references stop (no match) after a fixed
  amount of work.
- `read -e` uses the terminal driver's line editing, not the line editor.
- `<` and `>` in `[[ ]]` compare bytes, not the locale's collation.
- `declare -f` prints a function as it was written.
- Aliases expand when a command runs, not when it is read.
- Many interactive-only `shopt` names and some `set -o` names are accepted
  but change nothing.

### Compatibility corpus (proposed)

Add a CI job that runs a fixed set of real scripts under `bash` and `wsh` and
compares standard output, standard error and exit status. Good sources are
nvm (already done), `bash-completion` helpers, the scripts in this
repository, and small scripts from popular projects. Each difference is then
a bug or a line in "Known differences from Bash".

## Safer than Bash

### What wolysh does now

- **No partial runs on a syntax error.** wsh parses the whole script file
  before it runs any of it. Bash runs the lines before the error.
- **Syntax check without running:** `wsh --check script` and `wsh -n`.
- **Warnings in `wsh --check`** (done). They cover the common Bash mistakes:
  - An unquoted `$var` argument of `rm`, `mv`, `cp`, `rmdir`, `chmod` or
    `chown`.
  - `cd dir` with no check of its status.
  - `[ $x = y ]` with an unquoted `$x`.
  - A `for` loop over `$(ls)`.

  The warnings do not change the exit status unless `--strict` is given.
  Then a warning gives exit status 1. The
  [agent workflows guide](agent-workflows.md#validate-generated-scripts)
  lists the warning texts.
- **Limits instead of hangs or crashes:**
  - Function calls nest at most 256 levels.
  - Statement lists and `[[ ]]` groups nest at most 128 levels.
  - Arithmetic nests at most 1024 levels.
  - Brace expansion makes at most 4,194,304 words.
  - Arrays have at most 1,048,576 elements.
  - Regular expressions stop after a fixed number of steps.
- **Memory safety work on this branch:**
  - Uses after free, out-of-bounds slices, integer overflows and leaked
    descriptors are fixed. Each one has a case in `tests/guard_cases.sh`.
  - `-Dmem-guard` builds the shell on a checking allocator, and CI runs it.
  - Ownership rules for new code are in [memory.md](memory.md).

### What to add for 1.0 (proposed)

1. **`wsh --safe` (or `set -o safe`).** It turns on `errexit`, `nounset`,
   `pipefail` and `noclobber` together. It also stops a command when an
   unset or empty variable makes a dangerous path, for example
   `rm -rf "$dir/"*` with an empty `$dir`.
2. **Limit deep `$( $( ... ) )` and `eval` nesting.** Each nested piece is
   parsed separately, so the 128-level limit does not cover them all yet.
3. **Make the guarded test suite a release gate** (see "Release gates").
